# 実機で確かめること（iPhone・Android）

自動テストは Chromium だけです。下の項目は、実機で人が確かめる必要があります。
結果は ○（できた）／×（できない）／△（できるが気になる）と、端末名・OSの版・ブラウザ・イヤホンの種類を書いてください。

## 準備
- [ ] https のURLで開ける（置き場所が決まってから）
- [ ] LINEで送ったURLを開いた時、LINEの中ではなく Safari / Chrome で開く（URLの最後に `?openExternalBrowser=1`）
- [ ] LINEの中で開いてしまった時、上に「ブラウザで開いてください」の案内が出る

## MIDIを開く
- [ ] LINEで受け取ったMIDIをスマホに保存できる（iPhone：「ファイル」アプリ、Android：ダウンロード）
- [ ] 「MIDIを開く」から、そのファイルを選べる（灰色で選べない、にならない）
- [ ] パート名が文字化けしない

## 音
- [ ] ガイドが鳴る（iPhone は消音スイッチ＝マナーモードをONにした状態でも試す）
- [ ] 有線イヤホン／Bluetoothイヤホン（AirPodsなど）で鳴る
- [ ] カウント（カッ、カッ…）が鳴り、その後に歌が始まる
- [ ] ③④で、カウント中に自分の最初の音が鳴る

## 画面を切り替えても聴く（試作ブランチのみ。詳しい手順は handoff 文書の7.6）
- [ ] マイクOFFで再生 → 画面ロックで1曲分（5分程度）続く
- [ ] 別アプリ（LINEなど）への切り替え・ホーム画面でも続く
- [ ] 戻ると、聴いていた位置と譜面が合い、そのまま続く
- [ ] 全曲ループで曲の終わりを越えて先頭から続く／区間ループで数回繰り返す
- [ ] 自分だけ・段階・テンポ・キー・音色が、裏で聞こえる音にも反映され、戻っても変わらない
- [ ] ロック画面に曲名と、再生・一時停止・10秒送り／戻しが出て、効く
- [ ] イヤホンを抜く・アラーム・電話の後も、ロック画面とアプリの表示（再生中か・位置）が合う
- [ ] 区間・しおりのループ中に画面を離れると、ループが止まって曲の終わりまで流れる。戻ると「区間ループはオフ」と出て、「ループ」で同じ区間に戻せる
- [ ] 「練習の設定」で上の動きをオフにすると、画面を離れても区間を繰り返す
- [ ] 切り替えの瞬間の「プツッ」や隙間が気にならない
- [ ] 「？」の「状態」「直前」の表示（うまくいかない時に写真を撮る）

## マイク
- [ ] 「マイクをオン」で許可を求められ、許可すると「あなたの声」に音名が出る
- [ ] マイクをオンにしても、ガイドの音量が急に小さくならない（iPhoneで受話口から鳴る、などが起きないか）
- [ ] Bluetoothイヤホンで、マイクをオンにするとガイドの音質が電話のように悪くならないか
- [ ] 正しく歌った時に「合っています」が多く出る（Bluetoothでは「練習の設定 → 声の遅れ補正」を200〜300にして比べる）

## 練習の流れ
- [ ] 自分のパートを選び、次に別の曲を開いても同じパート名なら選ばれたまま
- [ ] 区間リピート：区間の中で繰り返し、回ごとの一致が並ぶ
- [ ] 練習中に画面が勝手に暗くならない
- [ ] マイクON・録音中にLINEなどへ切り替えると一時停止し、戻って「再生」で続きができる
- [ ] 電話がかかってきた時など、音が止められた後に「再生」で戻る

## 録音
- [ ] 録音→聴き返しで、自分の声とガイドが同時に聞こえ、ずれが気にならない
- [ ] 保存できる（iPhoneは保存先を選ぶ画面が出るか）
- [ ] 保存していない録音がある時に別の曲を開こうとすると、確認が出る

## 画面
- [ ] 練習中、音程バーと下の操作ボタンが同じ画面に収まる
- [ ] 横向きでも使える
- [ ] 文字やボタンが小さすぎない

## 曲専用リンク（共有APIを設定した後。試すのは合成のMIDIで）
- [ ] 「曲を開く」→「共有リンク」→「リンクを作る」で「リンクができました」と出る。メニューが共有の欄に重ならない
- [ ] 「コピー」でリンクがコピーできる（できない時は、リンクを長押ししてコピーできる）
- [ ] 「LINEで送る」でLINEが開き、曲名とリンクが入った状態になる
- [ ] LINEのトークでリンクを押す → LINEの中のブラウザで開いても、曲が読み込まれる（`#song=…` が消えない）
- [ ] 同じリンクをSafari（Android は Chrome）で開いても、曲が読み込まれる。自動で再生はしない
- [ ] 受け取った曲で、しおり・和音練習・録音が今まで通り使える
- [ ] 作った端末で「共有をやめる」→ もう一度リンクを開くと「この曲の共有は、やめられました」

### マイクONなのに音程が出ない端末（2026-11-06、iPad Pro 11インチとAndroidで報告）
- [ ] **最初に省電力モードを確認する**：Androidは「スーパーバッテリーセーバー」（通常のバッテリーセーバーも記録）、iPad/iPhoneは「低電力モード」。オンなら切って、マイクOFF→ONで再確認する
  - 2026-11-06：Androidでスーパーバッテリーセーバーを切ったら直った、とユーザーが報告。オンに戻して再発するかは未確認なので、原因はまだ仮説。iPadで同じ設定が関係するかも未確認
  - 省電力モードのオン／オフそれぞれで、下の「マイク診断」の結果を残すと原因を確定しやすい
- [ ] ボイスメモでは録音可能、Bluetooth接続なし、感度「高」でも無反応かを記録する
- [ ] 「練習の設定」→「マイク診断」を展開してからマイクON、声を3秒間伸ばす
- [ ] 入力トラック live / muted / ended と、音声処理 running / suspended を記録する
- [ ] 解析回数が増えるか、入力音量（RMS）が発声に合わせて変わるかを記録する
- [ ] RMSが増えているのに検出音程がない場合と、RMSがほぼゼロのままの場合を区別する
- [ ] 「診断結果をコピー」で文字列を共有する。音声自体は保存・送信しない
- [ ] 実機での原因はこの診断だけで断定しない。iPadOS版・Safari版と合わせて記録する
