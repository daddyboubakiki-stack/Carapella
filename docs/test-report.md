# テスト結果

実施：Claude（2026-10-29）。環境：Linux 上の Chromium（Playwright 1.63）、Node 22。
「確認方法」の区別：**再現**＝ブラウザで実際に起こした／**計算**＝取り出した関数に合成音を入れた／**コード**＝コードを読んだだけ（実行していない）／**未確認**。

マイクの代わりに「ガイド音をそのままマイクへ流す」仕掛けを使っています。人の声ではありません。

---

## 1回目：元の版（`main` の index.html）

### 動いたこと
- 判定（再現）：完璧に歌う 100%／30セント高い声は ふつう(±50) 99%・きびしい(±25) 0%／半音ずれ 0%／1オクターブ下は「オクターブ違いも正解」OFF 0%・ON 100%／低いパート 100%
- 音程推定（計算）：C2〜C6、44.1kHz・48kHz、倍音・基音が弱い声・雑音ありで、誤差5セント以内、オクターブの取り違え0。B1（62Hz）より低い音は拾わない（設計どおり）
- MIDI（計算）：format 0/1、Shift_JISのパート名・歌詞、テンポ変化、RIFF/RMID、5パート5分の曲、壊れたファイルのエラー表示
- 重さ（再現）：5パート5分＋マイクON＋再生中、CPUを6倍遅くしても 54fps
- スマホ幅 320〜390px で横はみ出しなし、ダークモードあり

### 見つかった問題
| | 起きること | 確認方法 | 改修版では |
|---|---|---|---|
| 1 | スマホで音程バーと再生ボタンが同時に見えない（5パートだと最初の画面はパート欄だけ） | 再現（実測） | 直した |
| 2 | スピーカーで使うと、歌わなくても100%になる | 再現 | ③④の段階では起きない（③で0%を確認）。①②では今も起きる |
| 3 | 遅れ補正が実際とずれると、完璧でも点が下がる（ずれ約0.2秒で83%、約0.4秒で50%、デモ曲の場合） | 再現 | 未対応（次の候補：遅れの自動測定） |
| 4 | 音が切り替わる瞬間が毎回「外れ」になる（完璧な声でも91〜97%） | 再現 | 未対応（次の候補：音の入りの猶予）。説明文は追加 |
| 5 | 別の曲を開くと、保存していない録音が確認なしで消える | 再現 | 直した（ページ内で確認） |
| 6 | 「きびしい」だとビブラートで点が下がる（振れ幅±30セントで77%、±50で35%） | 計算 | 未対応。説明文は追加 |
| 7 | 録音中にパートを切り替えられ、それまでの判定記録が消える | 押せるのは再現、消えるのはコード | 直した（録音中は切替不可） |
| 8 | カラオケ形式（.kar）の歌詞が出ない | 再現 | 対応済み（2026-10-29、テスト用ファイルで確認。実際の .kar は未確認） |
| 9 | 途中で切れたMIDIが、パートが欠けたまま黙って読み込まれる | 再現 | 未対応 |

### 確かめられなかったこと
- 別アプリに切り替えて戻った時のガイドの乱れ（テスト環境ではページの凍結を再現できず）→ 改修版では「切り替えたら一時停止」にした
- 聴き返しでの声とガイドのタイミング（測定値が0〜80ミリ秒でばらつき、環境の影響と区別できず）

## 2回目：改修版（Draft PR の index.html）

`npm run test:e2e`：**50項目すべて合格**。`npm run test:unit`：MIDI読み込みの結果は1回目と同じ（KARの歌詞は1回目と同じく未対応）。

追記（2026-10-29）：.kar の歌詞に対応し、テストの小節数の数え方をアプリ（`barCount`）に合わせた。`npm run test:unit` は NG 0件、`npm run test:e2e` も NG 0件。

| 項目 | 主な確認内容 | 結果 |
|---|---|---|
| 判定の回帰 | 1回目の7つの結果と同じか（±3%以内） | 7/7 同じ |
| 練習の段階 | ①は漏れで98%（問題2の再現）、③は0%、④は判定なし。③でカウント中に最初の音が鳴る、①では鳴らない | 合格 |
| カウントイン | 4回・間隔0.6秒（テンポ50%なら1.2秒）・1拍目が強拍・最後の1拍後に歌が始まる・カウント中に止めたら歌い出しの位置・シーク時はカウントしない | 合格 |
| 区間リピート | 初期値は今の小節から2小節、区間内を行き来、回ごとの一致（例：①98%→①97%→①98%）、カウントは毎回、区間の録音は1回で自動停止、録音中は切替不可、途中で止めても次は区間の始まりから | 合格 |
| 録音の保護 | 未保存があれば確認の帯、「やめる」で残る、読めないファイルでは消えない、保存済みなら確認なし、聴き返しできる | 合格 |
| スマホ向け | 画面切替で一時停止、音が止められたら一時停止→再生で復帰、audioSession（playback / play-and-record）、画面スリープ防止の要求と解除、再読み込み後もパート・段階・音名を記憶、LINE内で案内、タッチ端末で拡張子の絞り込みなし、Android相当の画面でタップ操作 | 合格 |
| 配置 | 390×664・375×548・412×780（Safariのツールバー分を引いた高さを想定）・1200×900で、音程バーと再生ボタンが同時に見える、横はみ出しなし | 合格 |

注意：iPhone の audioSession と画面スリープ防止は、テストでは「呼ばれたか」だけを確かめています（偽物に差し替え）。実機で効くかは未確認です。
