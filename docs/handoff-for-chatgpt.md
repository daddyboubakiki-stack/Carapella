## 1. これは何か

MIDIを開くと、パートごとの音程バーが流れ、マイクで歌った声の高さが線で重なるWebアプリ。`index.html` 1ファイル、外部ライブラリなし。

- MIDI読み込み：自前のパーサー（format 0/1、テンポ変化、拍子、歌詞 meta 0x05、Shift_JIS）
- 音程推定：McLeod Pitch Method（正規化自己相関）、3点の中央値でならす
- ガイド音：Web Audio のオシレーター（パートごとの音量・ミュート）
- 録音：MediaRecorder。聴き返しでは、ガイドと当時の音程の線も一緒に流す

元々は Claude のアーティファクトとして作られ、リンク共有中（https://claude.ai/artifact/TFiq6mhJFqtTW53EucSpxb）。`main` の index.html はそれと同じ内容。

## 2. 決まっていること

- ［決定］目的は、アカペラサークルの**個人の音取り**に絞る（バンド練で全員同時に使う用途は対象外）
- ［決定］サーバーが必要になるなら、MIDIは今まで通り LINE で送る（MIDIを預かる仕組みは作らない）
- ［決定］iPhone と Android の両方で使えるようにしたい
- ［決定］GitHub のリポジトリを作り、ChatGPT とも相談する
- ［決定］改修の優先順位は Claude の提案（下の A-1〜A-4）で進めてよい、と依頼された

## 3. 改修版でやったこと（Draft PR）

- A-1 スマホ向け画面：パート選択を横1行のチップに、再生などの操作を画面下に固定。パート別音量は折りたたみへ
- A-2 区間リピート：小節で指定。回ごとの一致率を表示。区間中の録音は1回で自動停止。再生・録音は必ず区間の始まりから
- A-3 カウントイン：拍子とテンポに合わせて1小節。再生ボタン・録音・区間の繰り返しの時だけ（シークでは鳴らさない）
- A-4 練習の段階：①一緒に（自分のガイド100%）→ ②小さく（30%）→ ③自分なし（0%）→ ④ひとりで（全部0%）。③④はカウント中に自分の最初の音を鳴らす
- スマホでの安定化：画面切替・音の中断で一時停止、画面スリープ防止（Wake Lock）、iPhone の消音スイッチ対策（`navigator.audioSession.type`）、LINE内ブラウザの案内、タッチ端末ではファイル選択の拡張子絞り込みをやめる、設定とパート名をlocalStorageに記憶
- 前回見つけた問題の修正：未保存の録音を消す前にページ内で確認（`confirm()` はアーティファクト内で使えないため）、録音中はパート・段階・区間を切り替えられない

教育面の設計メモ（Claude）：
- 段階は「足場を外していく」考え方。①で点が高くても、ガイドをなぞっているだけかもしれない、と画面に明記した（誤概念の予防）。番号は練習の順番の目安で、上手さの段位ではない
- 目標の音は平均律。和音の中では平均律からずらした方が響く場合がある（長3度は平均律より約13.7セント低い純正律）、と説明に書いた
- 学習効果は［未確認］（仮説）

## 5. わかった制約

- ［確認済み・Claudeが参照できるアーティファクトの仕様による］Claude のアーティファクトの中では、マイクは誰が見ても拒否される（実機では未確認）。**スマホでマイクを使うには、https の普通のWebページとして置く必要がある**
- ［確認済み・二次資料］iPhone の Web Audio は消音スイッチで鳴らなくなることがある。`navigator.audioSession` に対応した Safari ではその影響を減らせる（対応版は［未確認］）
- ［二次資料・2024年の記事］LINE で送る URL に `?openExternalBrowser=1` を付けると、外部ブラウザで開く
